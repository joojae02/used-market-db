# 예외·방어 테스트 목록 (AWS 운영 브랜치 기준)

범례: **자동** = `run.py --deep`로 실행, **추가** = 교수 시연 전 별도 구현·수동 검토 필요. 자동 테스트의 기대 HTTP 코드가 제품 요구사항과 충돌하면 합의된 명세를 기준으로 갱신해야 합니다.

## 1. 인증·세션 (자동)

| 검증 항목 | 세부 사례 |
|---|---|
| 비인증 접근 | 내 정보/내 상품/구매내역/내 신고/채팅/관리자 목록의 401 |
| 무효 토큰 | 빈 서명, 난수 문자열, 길이·특수문자 변형 토큰 45건 이상 |
| 잘못된 HTTP 메서드 | GET 대신 POST·PATCH·PUT·DELETE 등 405 |
| 잘못된 JSON | 잘린 본문, 객체 대신 숫자·배열·문자열·null, 잘못된 UTF-8 |
| 관리자 권한 | 일반회원이 회원조회·신고조회·회원제재·역할변경·게시글 조치·신고 처리 시도 |
| 로그인 | 미존재 닉네임, 비밀번호 불일치, 5회 실패 후 정확한 비밀번호도 잠금 |
| 세션 사용 | 탈퇴·정지 계정이 기존 토큰으로 접근하는 경우 |

## 2. 회원가입·계정 검증 (자동)

| 영역 | 세부 사례 |
|---|---|
| 필수 필드 | 성명·닉네임·전화·이메일·비밀번호 누락 또는 null |
| 최소 길이 | 성명 빈 문자열, 닉네임 0/1자, 패스워드 0~3자 |
| 최대 길이 | 성명 51·52·120·256·1024자, 닉네임 31·32·64·256자 |
| 최대 길이 | 패스워드 101·102·256·1024자, 주소 201·202·256·1024자 |
| 정상 경계 | 닉네임 2·30자, 비밀번호 4·100자 |
| 전화번호 | 국가번호, 문자 혼합, 짧거나 긴 자리수, 숫자 대신 기호, 공백·다른 구분자 |
| 이메일 | @ 누락, 도메인 누락, 공백 삽입, 형식 오류, 길이 초과 |
| 생년월일 | 2월 30일, 잘못된 날짜 문자열, JSON 배열 타입 |
| 타입 | 숫자 비밀번호, null/누락 필드, JSON 본문 형식 오류 |
| 중복 | 같은 닉네임·이메일·전화번호, 동시 동일 회원가입 요청 |
| 입력 퍼징 | 임의 길이·특수문자·숫자 난수의 잘못된 필드 수백~수천 건 |

## 3. 상품 등록·수정·삭제 (자동)

| 영역 | 세부 사례 |
|---|---|
| 가격 | -1, 큰 음수, 0, 1, 4294967294, 4294967295, 초과, 소수, NaN, Infinity, 빈 값 |
| 상품명 | 빈 값, 공백만, 1/100자 정상, 101자 이상 거부 |
| 필수 입력 | 제목·설명·가격·상태 누락 |
| 상태 Enum | 허용되지 않은 물품상태, 영문 상태 |
| 소유권 | 타인 상품 수정·삭제·예약·예약 해제·거래 완료 시도 |
| 존재 여부 | 존재하지 않는 상품 수정·삭제·예약·완료, 음수·0·초대형 ID |
| 삭제 상태 | 삭제 후 소유자·관리자는 열람, 제3자·익명은 차단, 재삭제·신규 채팅 차단 |
| 부작용 | 타인 수정 거부 후 원래 상품명 및 소유자 불변 |
| 이미지 파일 | .svg/.exe/.pdf/.jpg.exe, 가짜 .jpg/.png/.gif/.webp, 확장자·MIME 불일치 |
| DB 반영 | 이미지 실패 요청이 상품을 생성했는지, 정상 가격·상품명 저장 확인 |
| 생성형 퍼징 | 상품명, 가격, 상태의 임계값 밖 값 반복 생성 |

## 4. 채팅 (자동)

| 영역 | 세부 사례 |
|---|---|
| 본인 상품 | 판매자 자기 상품 채팅 금지 |
| 미존재 상품 | 존재하지 않는 ID로 방 개설 차단 |
| 중복 방 | 기존 구매자가 다시 생성하면 동일 room_no 반환 |
| 참여자 권한 | 비참여자가 채팅방 열람/메시지 송신 불가 |
| 비인증 권한 | 토큰 없는 메시지 등록·방 조회 거부 |
| 메시지 길이 | 0자/2001자 거부, 1자/2000자 성공 및 내용 보존 |
| 메시지 타입 | null, 숫자, bool, 필드 없음, 배열 등 거부 |
| 목록 | 채팅방은 판매자가 관리, 구매자는 타 구매자 목록 조회 불가 |
| 동시 개설 | 같은 구매자가 같은 상품 채팅방 다중 동시 생성 → 500 금지, room_no 유일 |
| 동시 DB 불변식 | 해당 상품·구매자 조합 방 1개만 존재 |

| 영역 | 세부 사례 |
|---|---|
| 예약 | 채팅 참여자만 예약 가능, 판매자만 지정 가능 |

| 예약중 삭제 | 예약중인 상품 삭제 금지 |
| 예약자 아닌 구매자 | 예약중 다른 구매자와 거래완료 차단 |
| 예약 해제 | 예약중일 때만 해제 가능, 연속 해제 거부 |
| 완료 | 정상 거래완료 후 상태/구매자 번호 보존 |
| 중복 완료 | 이미 완료한 상품 다시 완료 차단 |

| 동시 완료 | 판매자가 한 상품을 여러 번 동시 완료 → 정확히 한 건 성공 |

## 6. 신고·관리자 (자동)

| 영역 | 세부 사례 |
|---|---|
| 자기 신고 | 본인 회원/게시글 신고 거부 |
| 미존재 신고 대상 | 존재하지 않는 회원/상품 신고 거부 |
| 잘못된 신고 사유 | 사유 enum 밖 값·누락 필드·타입 이상·본문 길이 0/2001 |
| 중복 신고 | 동일 대상 같은/다른 사유로 두 번째 신고 거부 |
| 신고 검토 | 접수→검토중 1회, 중복 검토 시작 거부 |
| 신고 처리 | 처리완료·조치없음·반려, 빈 사유/501자/잘못된 결과 값 거부 |
| 처리 후 재처리 | 반려/처리완료 된 신고의 재처리 차단 |
| 제재 | 일반회원 제재 금지, 관리자의 자기 제재 금지, staff의 root 제재 금지 |
| 제재 입력 | 잘못된 제재 유형, 사유 빈값·501자, 종료시각 누락/과거/잘못된 날짜 |
| 제재 상태 | 경고는 정상 유지, 일시정지 계정 차단, 제재 해제 후 정상 복구 |
| 중복 제재 | 동일 회원에 대한 중복 일시정지 거부, 동시 제재 1건만 성공 |
| 시간대 | 시간대 포함 ISO 제재 종료시각이 HTTP 500을 유발하지 않아야 함 |
| root 보호 | root 자신의 역할 변경 불가, 타인에게 root 부여 불가, staff 역할 변경 불가 |

## 7. 검색·입력 보안·생존성 (자동)

| 영역 | 세부 사례 |
|---|---|
| SQL 파라미터화 | `' OR 1=1 --` 등 문자열을 로그인·상품 검색·관리자 검색에 삽입 |
| 특수문자 | `%`, `_`, `\\`, 따옴표, 공백, 한글, 이모지, 결합문자, bidi 제어문자 |
| 존재하지 않는 경로 | 알 수 없는 URL, 정수 대신 문자열, 음수·0·BIGINT 상한 ID |
| GET 응답 구조 | 상품·관리자 목록 JSON 배열, 상세 응답 필수 필드 확인 |
| 퍼징 후 생존성 | 모든 예외 및 동시 요청 후 health·상품 목록·관리자 API가 살아 있는지 |
| 성능 기초 | 각 케이스 지연시간, 전체 p50/p95, 테스트별 HTTP 0/500 기록 |

## 8. 실행에 아직 포함되지 않은 추가 고난도 시나리오

다음은 **별도 개발이 필요한 항목**입니다. 현재 ZIP으로 실행했다고 주장하지 않습니다.

- 프론트엔드 E2E: 제재 성공 alert 실제 표시, 제재 실패 시 성공 alert 미표시, 여러 번 클릭 중복 제출 방지.
- 버튼 연속 더블클릭, 브라우저 새로고침/뒤로가기/중복 탭 제출, 브라우저 오프라인 후 재시도.
- 브라우저 XSS 렌더링: 상품 설명·채팅·신고 내용에 HTML/스크립트 문자열 입력 후 실제 DOM 격리 확인.
- CSRF/CORS 정책 점검, HTTP 보안 헤더, 민감한 정보·스택트레이스 노출 검사.
- 유효기간 3600초 초과한 세션, 시스템시간 이동, 날짜경계/일광절약시간 입력.
- 회원 탈퇴 후 동일 이메일 재가입, 기존 채팅·상품·신고 기록의 소유권 처리.
- 50번 연속 로그인 실패 및 로그인 성공과 실패가 겹치는 동시 요청의 잠금 상태.
- 예약과 회원 탈퇴가 경합할 때 DB 최종 상태 일관성.
- 판매완료+게시글 삭제+제재 해제+다른 사용자 신고가 동시에 발생하는 복합 경합.
- S3 업로드 성공 후 DB INSERT 실패 시 고아 파일 처리, 이미지 교체 실패 시 원본 보존.
- 올바른 JPEG 헤더이지만 손상된 이미지, 거대 이미지, 픽셀 폭탄, 이미지 수량 상한.
- MySQL 연결 거부/재연결/데드락/락 대기 타임아웃 후 API의 롤백과 에러 노출.
- EC2 프로세스 재시작/컨테이너 재생성 후 로그인·상품·이미지 영속성.
- RDS 백업 복구 연습, 백업 복원 후 샘플 데이터 정합성 (반드시 별도 복원 DB).
- 계약·업무기술서의 구매자 요청→판매자 승인 흐름과 현재 판매자 단독 완료 구현 간 요구사항 일치 여부.

현재 구현은 **API/DB 수준의 격리형 통합 검사**입니다. 위 항목을 교수가 중점 확인한다면 Playwright 브라우저 테스트, S3 모킹, 장애 주입 테스트를 다음 단계로 추가해야 합니다.
